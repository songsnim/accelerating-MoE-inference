행은 거의 공짜다

측정 · matmul_transposed(q_proj)

포장이 왜 이득인지는 이 곡선 하나로 끝난다. q_proj 를 M 행만 넣고 한 번 부르는 데 걸리는 시간을 M=1 부터 40 까지 한 행씩 늘려가며 쟀다. M=1 이나 M=19 나 50 ms 대에서 거의 그대로다 (차이 9.4%). 호출 한 번의 값은 행 수가 아니라 가중치 33.55 MB 를 DRAM 에서 읽어오는 값이다. 행을 더 태우는 건 거의 덤이다.

같은 내적을 130번

같은 커밋에 딸려 들어간 두 번째 변경

포장을 하려면 어텐션을 model.cu 안에 다시 써야 했다 — layer.cu 는 수정 금지 파일이라 시퀀스 구간을 알려줄 방법이 없었기 때문이다. 그런데 다시 쓰는 김에 원본의 낭비도 같이 사라졌다. 원본은 같은 q·k 내적을 130번 다시 계산하고, 모든 원소를 Tensor::at() 로 만진다.

before

src/layer.cu
for ki: score = q·k // 1회 maxv = max(maxv, score/√d) for ki: score = q·k // 1회 denom += exp(score/√d - maxv) for d in 128: for ki: score = q·k // 128회 value += exp(...)/denom * v[ki][d] out.at(qi, qh*128+d) = value

after

src/model.cu · attend_sequence
for ki: score = q·k // 1회, 저장 weights[ki] = score/√d maxv = max(maxv, weights[ki]) for ki: weights[ki] = exp(weights[ki]-maxv) denom += weights[ki] for ki: w = weights[ki]/denom for d in 128: acc[d] += w * vrow[d] for d in 128: orow[d] = acc[d]

측정

스레드 1개 · 레이어 1개분

두 코드의 출력 max abs diff = 0.000e+00. 더하는 순서(d 오름차순, ki 오름차순)와 exp 를 double 로 계산해 float 로 내리는 것까지 그대로 옮겼기 때문이다. 빠져나간 것은 계산량뿐이고 결과는 비트까지 같다.

n=2 · 실측 3점

한 커밋에 두 가지가 들어갔으므로, 어느 쪽이 진짜 지렛대였는지는 가르는 빌드를 하나 더 만들어야 알 수 있다. 포장은 하되 어텐션은 원본(130회 재계산)을 그대로 둔 세 번째 빌드를 만들어 n=2 로 돌렸다.

실험 노트를 고쳐야 한다

docs/lab-note.md 의 EXP-001 은 이렇게 적혀 있다 — “130회 attention 재계산 제거분은 전체의 13%(1.15x)뿐. 2.88x의 주된 원인은 스레드 포화다.”

가르는 빌드가 말하는 것은 반대다. 어텐션 다시 쓰기가 1.82x 로 둘 중 큰 쪽이고, 포장은 1.59x 다. 그리고 포장의 이득도 “스레드 포화”가 아니다 — 위 곡선이 보여주듯 M=1 과 M=19 의 호출 시간은 같다. 포장이 줄인 것은 행당 시간이 아니라 호출 횟수다. 레이어마다 matmul 을 —.

이 실험이 어긴 규칙. CLAUDE.md 는 “반드시 1개의 가설씩”이라고 적어 두었다. EXP-001 은 두 개를 같이 바꿨고, 그래서 무엇이 레버인지 알아내는 데 빌드 하나와 런 하나가 더 들었다.
