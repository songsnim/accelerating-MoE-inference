EXP-003 → EXP-004 · 한 개 레이어를 나란히

한 번 올라간 활성값은 32개 레이어를 내려오지 않는다

EXP-003 에서 GEMM 과 MoE 는 이미 GPU 로 갔다. 그런데도 절반이 남아 있었다. layer norm 과 잔류 흐름의 덧셈이 CPU 에 남아 있었기 때문에, 레이어마다 309MB 짜리 행렬이 PCIe 를 네 번 건넜다. EXP-004 는 그 둘을 커널로 옮겨 잔류 흐름을 32개 레이어 내내 GPU 안에 붙잡아 둔다. 48.765s → 24.115s (2.02x). 그런데 이 실험의 알짜는 속도가 아니라, 커널을 host 와 비트 단위로 똑같이 만들어야 했던 이유다.

기록된 프로파일의 정체

기록에는 host layer norm 이 16.144초로 남아 있다. 그런데 산술만 재면 레이어당 29.3ms, 64번 다 합쳐도 1.9초다. 나머지는 어디서 왔나. EXP-003 의 루프는 레이어마다 결과를 담을 Tensor 를 새로 만든다 — Tensor normed(hidden.shape()). 이건 309MB 짜리 vector<float> 를 0으로 채우는 일이고, 그 크기의 할당은 운영체제에서 새 페이지를 받아오므로 79,212번의 page fault 가 따라온다. 실측 174.5ms. 산술의 6배다.

잔류 흐름이 GPU 에 상주하면 새 문제가 생긴다. MoE 는 다음 레이어의 입력을 0에서부터 누적하는데, 그 사이에도 이번 레이어의 값이 residual 덧셈에 아직 필요하다. EXP-004 는 스트림 버퍼를 두 개 잡고 레이어 끝에서 포인터만 std::swap 한다. 토큰 4개 × 4차원으로 줄여 직접 밟아보자.

float32 · 이 브라우저에서 직접

실수 덧셈은 순서를 바꿔도 같지만, float32 덧셈은 다르다. 더할 때마다 반올림하므로 더하는 순서가 답을 바꾼다. host 의 layer norm 은 4096개를 한 개의 누산기에 순서대로 더한다 (objdump 로 확인: vaddss 사슬, 벡터화도 FMA 도 없다). GPU 에서 자연스러운 방식은 256개 스레드가 나눠 더한 뒤 트리로 합치는 것이다. 아래 4096개 숫자로 두 방식을 다 해본다.
