# Prefill 처리량 기록

APSS26 · Phi-tiny-MoE Prefill · RTX 3090 1장

채점 대상인 배치 prefill 경로 `PhiTinyMoEModel::generate()`를 Stage 45까지 튜닝한 기록입니다. cuBLAS 없이 CUDA 커널을 전부 직접 작성했습니다. 무엇이 실제로 숫자를 움직였는지, 무엇이 그럴듯해 보였지만 아니었는지, 그리고 정확성 버그부터 측정 방법 자체의 함정(노드가 아니라 GPU 클럭 상태였다는 뒤늦은 발견)까지 정리합니다.

## 요약

| 지표 | 값 |
|---|---|
| 베이스라인 | 0.0302 seq/s (단일 시퀀스, 33.15초 — 최적화 이전 OpenMP 루프) |
| 현재 (Stage 45) | ~595 seq/s (n=1024, 정상 클럭 GPU(≈1900MHz) 기준, validation 통과) |
| 누적 속도 향상 | ~19,700× |
| 채택 / 되돌림 / 버그 수정 | 38건 / 24건 / 6건 |

> **중요한 정정**: 이전에는 "특정 GPU 노드(b7)가 다른 노드보다 항상 약 15% 느리다"(Stage 18)고 결론 내렸지만, 이는 **Stage 39–40에서 뒤집혔습니다**. 실제 원인은 노드 정체성이 아니라 **GPU 클럭·전력 상태**였습니다. 정상 상태의 GPU는 1905MHz로 부스트했다가 370W 전력 상한에 걸려 ~1600MHz로 가라앉고, "느려" 보이는 GPU는 애초에 1395MHz에 눌어붙어 전력·온도 여유를 남긴 채 돕니다. 그래서 노드 이름이 아니라 `nvidia-smi --query-gpu=clocks.sm,power.draw,clocks_throttle_reasons.active`로 클럭을 직접 확인해야 하며, 이 발견 자체도 한 번 사람을 속여 클럭 운으로 이득처럼 보였던 GEMM 개선 하나가 제출까지 갔다가 커널 단위 재확인 끝에 되돌려졌습니다(Stage 40).

## 2. 기법 정리

### 채택됨 (38건)

1. **로우 포인터 인덱싱** (11.2×) — hot한 matmul·attention 루프에서 경계 검사가 들어간 `.at()`/`offset()` 호출 제거.
2. **OpenMP attention + score 버퍼 캐싱** (Stage 1에 포함) — 직렬 루프 병렬화, QK 내적 캐싱.
3. **시퀀스를 텐서 하나로 배칭** (~3×) — `[batch·seq, H]` 텐서 하나로 32개 레이어 통과.
4. **길이 기준 버킷팅** (여러 차례 재조정) — 버킷 자신의 최대 길이까지만 패딩.
5. **GPU 완전 상주(residency)** (43.2초 → 채점 조건 첫 통과) — `DeviceTensor`로 host↔device 왕복 제거.
6. **layer_norm 행별 순차 합산** (속도가 아니라 정확도) — host 합산 순서와 일치, 라우팅 타이 플립 방지.
7. **2D 레지스터 블로킹(GEMM 타일링)** (43.2초 → 17.5초) — 스레드당 Reg×Reg 서브블록.
8. **Attention shared memory K/V 재사용** (15.44초 → 15.10초) — 블록당 K/V 1회 로드.
9. **함수 내부 static 스크래치 버퍼** (67.9 → 86.5 seq/s) — 재사용 범위를 호출 지점으로 좁힘.
10. **MoE grouped GEMM + atomicAdd 수정** (86.5 → 96.9 seq/s) — 16개 expert 한 번의 launch로, race 수정.
11. **GEMM 타일 로드 coalescing** (106 → 145 seq/s) — shared 타일 인덱스 매핑 교체.
12. **임베딩 조회를 device로** (Stage 7에 포함) — 토큰 id를 행 인덱스로 직접 gather.
13. **float4 벡터화 로드 + 8×8 타일링** (154 → 225 seq/s) — 글로벌·shared 4개씩 로드/스토어.
14. **memcpy로 결과 복사** (225 → 233.5 seq/s) — 3,280만 회 `.at()` 루프 제거.
15. **GEMM 모양별 MoE 타일 폭 + epilogue 융합** (235 → 247 seq/s) — BN=64/128 분리, bias·silu 흡수.
16. **RoPE coalescing + MoE pull 방식 결합** (245 → 258 seq/s) — 블록당 행, atomic 대신 pull.
17. **router 좁은 타일 + 스트림 + layer_norm 2단계** (258 → 281 seq/s).
18. **전치된(K,N축 우선) 가중치 레이아웃** (296 → 320 seq/s) — 연속된 워프 read.
19. **QKV 프로젝션 융합** (320 seq/s, 속도 유지) — 구조 단순화 + 디바이스 메모리 1.5GB 절약.
20. **버킷 파이프라이닝(멀티 드라이버 스레드)** (320 → 344 seq/s).
21. **드라이버 수 + layer_norm 언롤 재조정** (344 → 349 seq/s).
22. **Prefix 중복 제거(trie)** (349 → ~470 seq/s, +21~23%) — 단일 변경 중 최대 개선.
23. **shared memory bank-conflict 해소** (+1.1~2.7%).
24. **시퀀스별 attention 길이 사용** (+1.5~2.4%, 빠른 노드 기준).
25. **결과 복사 경로 정리(pinned 다운로드 + 버퍼 재사용)** (481 → 514 seq/s, +6.7%).
26. **attention score 배열을 레지스터로** (끝단 +2.0%대, 3/3 일관) — `-Xptxas -v`로 local memory 발견.
27. **silu epilogue 융합 + `__restrict__` 전면 적용** (끝단 +0.9%대).
28. **MoE dispatch gather를 GEMM A 로더에 융합** (끝단 +1.9%) — 레이어당 ~540MB 트래픽 제거.
29. **attention: V 대신 행 인덱스만 staging** (끝단 +0.4%).
30. **RoPE를 QKV GEMM epilogue로 융합** (끝단 +0.6%) — FMA 축약 오차 발견·수정.
31. **이중 버퍼링 k-loop, BK=16** (끝단 +2.6%) — 과거 실패한 두 기법을 결합.
32. **B 타일에 cp.async 적용** (끝단 +0.51%) — Stage 15 실패를 뒤집음.
33. **grouped GEMM에도 동일한 이중 버퍼링·cp.async** (끝단 +0.59%).
34. **grouped GEMM L2 타일 스위즐(w13)** (끝단 +1.75%).
35. **A 타일 shared STORE의 bank-conflict 회전** (메인 +0.42% / grouped w2 끝단 +1.27%대).
36. **grouped GEMM epilogue를 float4 스토어로** (w2 커널 −3.5%).
37. **마지막 레이어는 필요한 행만 계산** (끝단 +2.07% — 최근 구간 최대 개선).
38. **logits 복사를 CPU 8스레드로 병렬화** (끝단 +0.48%).

### 시도 후 되돌림 (24건)

1. **32×32 타일, 1024스레드 블록** (43.2초 → 72.8초) — 점유율 1블록/SM으로 붕괴.
2. **16×16 타일에서 K-청크를 64로 확장** (43.2초 → 68.9초).
3. **Reg=8 타일링(초기 시도)** (18.3초 → 21.3초) — 작은 N에 스레드 낭비.
4. **스크래치 버퍼를 클래스 멤버로** (n=1024에서 OOM).
5. **텐서 코어(TF32/WMMA)** (n=8에서 validation 실패) — 방향성 있는 정밀도 오차.
6. **layer_norm coalescing 재설계** (약 4% 느려짐).
7. **GPU 측 MoE 라우팅 재작성** (구현하지 않음) — host 비용이 실은 2%뿐.
8. **RoPE 삼각함수를 head 루프 밖으로** (210 → 202 seq/s) — 지역성 악화.
9. **레지스터 prefetch 소프트웨어 파이프라이닝** (233.5 → 206 seq/s) — 상주 블록 2→1.
10. **CUTLASS 식 L2 블록 스위즐** (1982ms → 2044ms).
11. **cp.async prefetch(싱글·더블 버퍼)** (296 → 265–306 seq/s) — 당시엔 지연시간 병목이 아니었음.
12. **`__launch_bounds__`로 점유율 강제 상향** (258 → 33 seq/s) — 레지스터 스필로 치명적.
13. **attention에서 K·V shared 버퍼 공유** (258 → 212 seq/s).
14. **⟨RegM=8, RegN=4⟩ 메인 GEMM 타일** (n=512에서는 이겼지만 n=1024에서는 짐).
15. **Pinned host 스테이징 버퍼** (노드 고정 A/B 기준 사실상 동일) — 전송이 전체의 0.4%뿐.
16. **작업량 기준 버킷 분할** (−0.4~1.1%).
17. **Fused shared-memory layer_norm(2회 재검증)** (−3% / ncu 기준 2.46배 느림).
18. **MoE 라우팅 host 스크래치 재사용** (끝단 평균 −0.37%) — 이미 다른 드라이버에 가려짐.
19. **attention 블록 순서·shared V 제거 재시도** (끝단 중립) — 레지스터 한계에 다시 막힘.
20. **layer_norm apply를 GEMM 로더에 융합** (중립 → −5~10%) — 128레지스터 한도 초과.
21. **router 타일을 BM=128로, BK=32→16 재시도** (중립 / −6.5~7.9%).
22. **attention blockDim 축소·key 조기 종료·버킷 3개** (끝단 노이즈, 커널 단위론 손해).
23. **메인 GEMM에 L2 타일 스위즐 재시도** (잠깐 제출됐다가 되돌림) — 클럭 운이 만든 착시.
24. **attention의 sK staging 제거** (끝단 −1.63%) — 레지스터 64→89.

## 3. 스테이지 로그 (Stage 1 – 45)

- **S1** (0.28 seq/s) CPU 코드 정리 — `.at()`/`offset()` 제거, attention 병렬화, score 캐싱.
- **S2** (0.85 seq/s) CPU 배칭 — 텐서 하나로 32개 레이어 통과.
- **S3a→3b** (23.7 seq/s) GPU 상주 — 상태 없는 H2D/D2H(3a) 실패, 완전 상주(3b)로 해결 + layer_norm 순서 버그 발견.
- **S4** (66.3 seq/s) GEMM 타일링 + 버킷 튜닝.
- **S5** (67.8 seq/s) Attention K/V shared memory.
- **S6** (86.5 seq/s) 스코프를 좁힌 스크래치 재사용 — 첫 시도 OOM, static 지역 변수로 해결.
- **텐서 코어 — 되돌림** — TF32 WMMA GEMM, n=8에서 validation 실패, 방향성 오차 확인.
- **MoE** (96.9 seq/s) Grouped expert GEMM — scatter-add race condition 발견·수정(atomicAdd).
- **S7** (154 seq/s) MoE 집중 리뷰 — dead-zone 제거, 임베딩 device 조회, 타일 coalescing.
- **S8** (225 seq/s) 메모리 접근 패스 — float4, 8×8 타일링, attention 재구성.
- **S9** (235 seq/s) 호스트 정리 + GEMM 한계 탐색 — memcpy, 레지스터 병목 확인.
- **S10** (247 seq/s) MoE 타일 특화 — 모양별 타일 폭, epilogue 융합.
- **S11** (258 seq/s) GEMM 외 나머지 24% — RoPE, MoE pull 결합, residual 흡수.
- **S12** (258 seq/s, 무변화) 점유율·분기·대역폭 점검 — 레지스터/점유율 표 확보.
- **S13** (281 seq/s) 스레드 블록 스케줄링 — router 좁은 타일, layer_norm 2단계, 동시 스트림.
- **S14** (296 seq/s) run.sh + 가중치 융합 — `-w` 기본화, w1/w3 융합.
- **S15** (320 seq/s) 전치된 가중치 레이아웃 — cp.async는 이 시점에 실패.
- **S16** (320 seq/s, 무변화) QKV 프로젝션 융합 — 구조 단순화, 메모리 1.5GB 절약, 헤더 의존성 빌드 버그 발견.
- **S17** (344 seq/s) 버킷 파이프라이닝 — 멀티 드라이버 스레드, race condition·가짜 속도 버그 발견.
- **S18** (—) 측정 방법론 재점검 — b7 노드가 느리다는 발견(*후에 뒤집힘, 아래 참고*), pinned 스테이징 되돌림.
- **S19** (349 seq/s) 드라이버 수 + layer_norm 언롤 재조정.
- **S20** (~470 seq/s) Prefix 중복 제거 — 21,376행 → 16,414 trie 노드(−23.2%), 버킷 8→2.
- **S21** (~490 seq/s) dedup 이후 3가지 실험 — bank-conflict 해소·시퀀스별 attention 길이 채택, 작업량 기준 분할은 손해.
- **S22** (—) fused layer_norm 재검증 — 여전히 2.46배 느림, ncu로 원인 재확인.
- **S23** (514 seq/s) 결과 복사 경로 정리 — pinned 버퍼, 출력 텐서 재할당 제거(+6.7%).
- **S24** (520 seq/s) reduction/동기화 최종 점검 — layer_norm 언롤 32→16.
- **S25** (끝단 −0.4%) MoE 라우팅 host 스크래치 재사용 — 되돌림, "GPU 라우팅 이전" 아이디어 종결.
- **S26** (끝단 +2.0%) attention score를 레지스터로 — 스택 프레임 128B 발견·제거.
- **S27** (끝단 +0.9%) silu epilogue 융합 + `__restrict__`.
- **S28** (끝단 +1.9%) MoE dispatch gather를 GEMM 로더로.
- **S29** (끝단 중립) layer_norm apply 융합 — 대부분 되돌림, 레지스터 128 한도 확인.
- **S30** (끝단 +0.4%) attention: V 대신 행 인덱스만 staging.
- **S31** (끝단 +0.6%) RoPE를 QKV GEMM epilogue로 융합 — FMA 축약 오차 발견·수정.
- **S32** (끝단 중립) router 타일·BK 재시도 — 되돌림.
- **S33** (끝단 +2.6%) 이중 버퍼링 k-loop, BK=16 — 과거 두 실패를 결합해 성공.
- **S34** (끝단 +0.51%) B 타일에 cp.async — Stage 15 실패를 뒤집음.
- **S35** (끝단 +0.59%) grouped GEMM에도 동일 적용.
- **S36** (무변화) sm_86 체크리스트 점검 — ncu `--launch-skip` 신뢰 불가 확인.
- **S37** (노이즈) 네 가지 재시도 — 전부 되돌림, 끝단 노이즈와 커널 실측의 괴리 확인.
- **S38** (끝단 +1.75%) grouped GEMM L2 타일 스위즐(w13) — 측정법 교정(스트림 합집합), `__expf` 오염 버그 발견·복구.
- **S39** (끝단 +0.42%) A 타일 스토어 bank-conflict 회전(메인 GEMM만).
- **S40** (결론: 노드=클럭 상태) L2 스위즐 재시도 되돌림 — Stage 18의 결론이 실은 GPU 클럭·전력 상태 문제였음을 발견.
- **S41** (w2 커널 −3.5%) grouped GEMM epilogue를 float4 스토어로 — lg_throttle 실제 원인 규명.
- **S42** (끝단 +2.07%) 마지막 레이어는 필요한 행만 — 최근 구간 최대 개선.
- **S43** (무변화) layer_norm 외부 리뷰 재검증 — 리뷰의 원인 진단이 실은 반대 방향이었음을 확인.
- **S44** (끝단 +1.27%) Stage 39 회전을 grouped GEMM w2에만 — 인스턴스별 측정으로 상쇄 효과 해소.
- **S45** (끝단 +0.48%) logits 복사를 CPU 8스레드로 — CPU GEMM 오프로딩은 산수로 이미 손해임을 먼저 확인.

## 4. 교훈

1. **배치 크기 앞에서 정직하기** — 타일 모양·최적값은 배치 크기에 따라 순위가 뒤집힌다. 오직 실제 채점 규모(n=1024)에서 측정한 숫자만 믿을 수 있다.
2. **결정으로 이어지는 reduction** — float32 합산 순서 변화 자체는 무해하지만, MoE 라우팅처럼 이산적 결정을 내리는 reduction에서는 host와 순서를 맞춰야 한다.
3. **블로킹 호출 자체는 비용이 아니다** — 겉보기엔 "host 시간 64%"였지만 실은 GPU 파이프라인이 동기화 시점에 비워지는 시간이었다. 실제 제거 가능한 비용을 먼저 재야 한다.
4. **병합된 실행이 새로운 race를 만들 수 있다** — 독립된 연산을 하나의 커널 실행으로 합칠 때는 "로직 보존"을 가정하지 말고 명시적으로 정확성을 증명해야 한다.
5. **하드웨어 자체도 변수다** (Stage 18, *이후 정정됨*) — 처음엔 특정 노드가 느리다고 여겼다.
6. **GPU가 roof에 닿으면 host 코드를 다시 보라** — 모든 GPU 프로파일러가 놓치는 host 측 0-채움·페이지 폴트에서 +6.7%가 나왔다.
7. **지표는 원인이 아니라 자원을 가리킨다** — `lg_throttle`을 "L2 용량 문제"로 오진단해 만든 수정이 엉뚱한 커널에서만 통했다. 카운터가 가리키는 건 병목 자원이지, 병목의 진짜 원인이 아니다.
8. **노드 이름이 아니라 클럭을 확인하라** — "특정 노드가 항상 느리다"는 결론(교훈 5)은 사실 GPU 클럭·전력 상태 문제였다. 같은 물리 노드도 시점에 따라 빠르거나 느릴 수 있으므로, 벤치마크 전엔 항상 클럭을 직접 측정해야 한다.

## 5. 과제 제약 (참고)

| 항목 | 내용 |
|---|---|
| 채점 대상 경로 | `generate()` prefill만 해당 — `generate_decode()`는 채점되지 않음 |
| 하드웨어 | 4장 중 RTX 3090 1장 사용, Slurm 파티션 제한 2분 |
| 허용 | Pthread, OpenMP, 직접 작성한 CUDA 커널 |
| 금지 | cuBLAS, cuDNN 등 외부 수학 라이브러리, 입력 내용에 특화된 분기 |
| 실제 채점 | `aps-submit`으로 제출된 코드만 채점됨 — 연습 대시보드(`./submit.sh`) 점수는 클럭 편차의 영향을 그대로 받아 참고용일 뿐 |

수치는 `aps` 파티션에서 `-n 1024 -v`를 반복 실행한 소요 시간·처리량의 median이며, 모든 수치는 validation PASSED를 전제로 합니다. Stage 18의 "특정 노드가 느리다"는 결론은 Stage 39–40에서 뒤집혔습니다 — 실은 GPU 클럭·전력 상태의 문제였고, 노드 이름이 아니라 `nvidia-smi`로 클럭을 확인하고 같은 `srun` 안에서 조건을 고정한 A/B 비교만 신뢰합니다.
